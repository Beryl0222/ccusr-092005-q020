# 传统老汤批次传承

记录甏肉老汤、香料包、肉类与配菜在门店之间的批次沿袭和风味检测：每次
**分装、续汤、合并、加热、过滤、跨店移交**都形成父子谱系，香料、肉类、
过敏原、下料温度与感官/微生物检测绑定实际批次。

## 能力

- **事件驱动的代际谱系**（`broth_lineage/service.py`）
  - 分装 `split`、续汤 `topup`（代际 +1）、跨店合并 `merge`（多父本）、
    加热 `heat`、过滤 `filter`、移交 `transfer`（在途分装）、烹制 `cook`。
  - 烹制把老汤、实际原料批次、八十摄氏度下料温度、成品（消费批次）连成图。
- **离线补传与重复扫码**：事件以客户端 `event_id` 幂等受理；同号不同载荷
  拒绝并指出冲突字段；补传按**发生时间**排序生效，重放不产生第二条边。
- **冻结守卫**：已冻结/隔离/报废的汤底不能进入任何新制作；被拒事件不落库。
- **异常圈定与处置**：微生物或感官异常自动冻结风险源并开立异常单；
  `incident_scope` 沿谱系只圈定后代支系（成品、在途分装），不波及父母汤
  与兄弟支系。食品安全负责人可选择 **报废 / 隔离观察 / 复检 / 恢复**，
  恢复必须有异常开立后的复检合格记录，全部处置决定留痕可追溯。
- **角色权限**：配方比例仅传承人（可写）与质控（只读）可见；检测由质控/
  传承人登记；处置仅食品安全负责人；门店员工扫码上报。
- **顾客脱敏查询**：凭消费批次仅返回脱敏批次号、老汤代际、门店与过敏原
  说明及安全提示，不含供应商、配方比例与内部完整批号。
- **持久化**：SQLite 落盘，服务重启后谱系、冻结状态、处置记录连续不中断。

## 数据与演示

`fixtures/seed.json` 是完整剧情：总店 326 代老汤与城南分店 210 代支脉分别
移交高铁新城分店后**跨店合并**（327 代），合并批次烹制的狮子头被判定
感官异常，系统圈定同汤成品与在途分装供负责人处置。

```python
from project_data import build_service
from broth_lineage import Role

svc = build_service("lineage.db")
svc.incident_scope(incident_id)          # 圈定异常支系
svc.trace("product", "prod-lion-0923", Role.QC)   # 任一成品追到每代老汤
svc.public_product_view("prod-lion-0919")         # 顾客脱敏视图
```

`python3 -m unittest discover -s tests`（或 `pytest`）可验证全部场景：
跨店合并谱系、重复扫码/载荷冲突、离线按发生时间补传、冻结拦截、异常支系
圈定不伤及无关支系、报废—复检—恢复流、重启连续性、角色权限与脱敏。
